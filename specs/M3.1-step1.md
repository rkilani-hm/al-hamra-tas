# M3.1-step1 — Config Write Authorization (SYSTEM_ADMIN) (Spec)

## Objective
Unblock configuration writes. Today the M0.2 config screens (org structure, job catalog, lookups, JD templates) and the M1.5/M1.6 config (pipeline stages, screening scorecards/criteria) fail-soft ("Could not save") because their writes are service-role-only with no authorized path. This module routes those config writes through authenticated SECURITY DEFINER RPCs that assert the caller is SYSTEM_ADMIN — so the signed-in admin can build the real Al Hamra org/config now. Mirrors the proven M0.1-admin-ui pattern (_is_system_admin() + definer RPC). This is STEP 1 of M3.1; the full dynamic permission model is step 2 — do NOT build dynamic permissions here, just the SYSTEM_ADMIN config unblock.

## Decisions (locked)
- Enforcement pattern: definer RPCs with in-function SYSTEM_ADMIN assertion (reuse/centralize the _is_system_admin() helper from M0.1-admin-ui — do NOT duplicate it; if it lives in a prior migration, reference it; if it needs to be a shared helper, ensure one canonical definition).
- Gate: SYSTEM_ADMIN only for ALL config writes in this step. (HR_MANAGER and finer permissions come in step 2's dynamic model — not now.)
- Scope: config is org-wide/global (no per-scope check on config writes).
- Reuse existing config tables — NO new tables. Only new config-write RPCs + rewiring the config UI screens to call them instead of direct PostgREST writes.
- Reads stay as-is (already authenticated). Only WRITES are being routed through RPCs.

- Gate the config screens' write controls (Add/Edit/Save buttons) on useAuth().roles including SYSTEM_ADMIN — hide/disable for non-admins so there are no dead buttons. (Step 2 generalizes this to permissions.)

## Edge cases
- Verify each config table's REAL schema before writing its RPC (columns, status enums, unique indexes) — do not assume from the spec; prior modules drifted. Flag any divergence.
- _is_system_admin() reuse: ensure ONE canonical definition; don't create a second.
- A config screen that already writes successfully (if any) — leave it; only rewire the failing ones.
- Non-admin reaching a config screen: write controls hidden/disabled; RPC rejects as backstop.
- Editing vs creating (p_id null = create, present = update) handled in each upsert.
