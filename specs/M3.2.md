# M3.2 — Admin & System Settings (Spec)

## Objective
A dedicated SYSTEM_ADMIN surface for app-wide settings (key/value store) plus a unified view/toggle of the dormant integration adapters (comm / storage / HRMS). Complements M0.1 admin UI (users/roles) and M3.1-step2a (permission matrix). Bilingual EN/AR, RTL. New key `settings.manage` (SYSTEM_ADMIN).

## Data model
- `tas_system_setting` — key text unique; value_json jsonb; category text; description text; +audit +trigger. Seed defaults (default_language, careers_portal_enabled, org_name_en, org_name_ar).
- RLS authenticated SELECT; writes via SECURITY DEFINER RPCs.

## New key
`settings.manage` seeded (area 'settings') + granted SYSTEM_ADMIN only.

## RPCs (gate settings.manage)
- `list_system_settings()` → jsonb (settings rows).
- `set_system_setting(p_key, p_value jsonb)` → void — upsert on key (unique; rubric 12).
- `list_adapters()` → jsonb — unified read of tas_comm_adapter_config / tas_storage_adapter_config / tas_hrms_adapter_config with a `kind` label.
- `set_adapter_enabled(p_kind, p_provider, p_enabled)` → void — route by kind ('comm','storage','hrms') to the right adapter table; audit.
- Migration: 14-digit ts sorts last; RLS+grants; ON CONFLICT rubric-12 (setting key unique); no storage bucket literal; no recursive CTE; idempotent.

## Feature — src/features/settings
- api.ts (interim loose-cast), types.ts.
- Route `/app/admin/settings` — system settings editor (key/value) + adapter toggles table (kind, provider, enabled switch, config status). Admin-only sidebar entry (system-admin gated like users/roles).
- Gate on `settings.manage`; SYSTEM_ADMIN passes; loading→disabled.

## i18n
Full `settings.*` namespace EN/AR (ar key-complete) + nav.systemSettings.

## DoD
tsc 0; /app/admin/settings 200; ar parity; RLS+grants+key; adapter toggles route correctly; interim casts flagged.
