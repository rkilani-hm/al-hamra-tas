# M1.6 — Screening & Shortlisting (Spec)

## Objective
A thin screening layer on top of M1.5. Recruiters screen applications sitting in the screening stage using a CONFIGURABLE scorecard (reusable criteria, bilingual), record an overall score + recommendation, and act: shortlist or reject — which moves the application stage via the EXISTING M1.5 move_application_stage RPC. NOT a workflow-engine module (no submit_workflow). Direct recruiter action. Reuses M1.5 applications/stages and M0.5 <AuditTrail>.

## Decisions (locked)
- Scoring: a CONFIGURABLE screening scorecard — reusable criteria (bilingual), each scored; overall score computed; recommendation (shortlist/reject/hold). Sets the pattern M1.7 (interview scorecards) and M1.8 (assessment) will reuse.
- Action model: DIRECT recruiter action. Recording a screening decision of "shortlist" calls the existing move_application_stage to the Shortlisted stage; "reject" calls set_application_status / move to a rejected stage. NO workflow engine.
- Bilingual criteria + UI; RTL. Internal screening notes EN-only is fine.
- Writes: authenticated-callable via SECURITY DEFINER RPCs (recruiters operate screening), same pattern as M1.5; scorecard CONFIG (criteria templates) writes service-role until M3.1.

### RPCs (security definer, transactional)
- list_screening_scorecards(): active scorecards + their criteria (ordered). Authenticated.
- create_screening(p_application_id uuid, p_scorecard_id uuid): create a draft screening for an application; return id. Authenticated.
- save_screening_scores(p_screening_id uuid, p_scores jsonb): jsonb array [{criterion_id, score, note}]; upsert tas_screening_score rows (ON CONFLICT (screening_id, criterion_id) DO UPDATE — this index is plain non-partial, so this is fine); recompute overall_score (weighted average using criterion weight); persist. Authenticated.
- submit_screening(p_screening_id uuid, p_recommendation text, p_notes_en text): set recommendation + notes, status 'submitted', screened_at; THEN act on the application via M1.5:
    - 'shortlist' -> move_application_stage(application, <Shortlisted stage id>, 'Screening: shortlisted')
    - 'reject'    -> set_application_status(application, 'rejected', 'Screening: rejected') (or move to rejected stage — use whichever M1.5 path is canonical; prefer move to the rejected stage so history + status both update)
    - 'hold'      -> no stage change, just record
  audit_log('M1.6','screening.submitted',...). Authenticated. Resolve the Shortlisted / Rejected stage by stage_type or code from tas_pipeline_stage.
- screening_detail(p_application_id uuid): the application's screening record(s) + scores + scorecard criteria (for display). Authenticated.
Grant EXECUTE to authenticated on all the above; scorecard/criteria CONFIG writes stay service-role (comment M3.1).

## Edge cases
- Screening an application not in the screening stage: allow (recruiter may screen anytime); the shortlist/reject action still moves the stage appropriately.
- Re-screening: allow multiple screening records OR update the existing draft — keep simple: one active draft per application; submitting finalizes it. New screening after a submitted one allowed (records keep history).
- Shortlisted/Rejected stage missing from pipeline: resolve by stage_type; if none found, record screening but skip the move + surface a clear message (don't crash).
- currentUserId null (Entra last): screened_by null; gate "my screenings" style views; no crash.
- Weighted overall: if all weights equal it's a simple average; guard divide-by-zero (no criteria scored -> overall null).
