# M2.4 — Reporting & Analytics Dashboards (Spec)

## Objective
Native recruitment KPI dashboard (no Power BI, no external service): headline counts + pipeline funnel + offer/source breakdowns aggregated from existing tables. Bilingual EN/AR, RTL. Gated on the EXISTING `report.view` key (no new key). SYSTEM_ADMIN bypasses.

## Data access
- `recruitment_kpis()` → jsonb (SECURITY DEFINER, gate `report.view`, EXECUTE authenticated) returning:
  - open_requisitions (status='published'), active_applications (status='active'), offers_pending (offer in_approval/issued), hires (application status='hired')
  - by_stage: [{stage_id, name_en, name_ar, count}] over active applications
  - offers_by_status: [{status, count}]
  - applications_by_source: [{source, count}]
- No new table, no new key. Migration = one RPC + grant. No storage bucket literal; no recursive CTE; idempotent.

## Feature — src/features/reports
- api.ts (interim loose-cast), types.ts.
- Route `/app/reports` — KPI cards + a simple native bar funnel (CSS bars, no chart lib) + offer/source breakdowns. Update sidebar `nav.reports` to point to `/app/reports` (currently `/app`).
- Gate the RPC read on report.view server-side; UI shows an empty/permission state if the read errors. loading→skeleton.

## i18n
Full `reports.*` namespace EN/AR (ar key-complete).
