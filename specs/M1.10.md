# M1.10 — Pre-Boarding & Document Collection (Spec)

## Objective
After an offer is accepted (M1.9 sets `tas_offer.onboarding_ready = true`), collect the new hire's mandatory documents (Civil ID, passport, visa/residency, certificates) against a checklist, track each item's collection/verification status, and gate a "pre-boarding complete" milestone that feeds M1.11 (Onboarding & MenaME handoff). Bilingual EN/AR, full RTL. RBAC-gated on a new capability `preboarding.manage`. Reuses the M0.5 `DocumentPanel` + `tas_document` store (no new storage). SYSTEM_ADMIN bypasses (via `_has_permission`).

## Data model (new tables)
- `tas_preboarding` — one per accepted-offer application.
  - id uuid pk; application_id uuid **unique** not null (fk tas_application); candidate_id uuid (fk tas_candidate); offer_id uuid (fk tas_offer);
  - status text not null default 'in_progress' check in ('in_progress','completed','cancelled');
  - started_at timestamptz default now(); completed_at timestamptz; completed_by uuid (fk tas_user); notes text;
  - created_at/created_by/updated_at/updated_by (standard, + `tas_set_updated_at` trigger).
- `tas_preboarding_item` — checklist rows.
  - id uuid pk; preboarding_id uuid not null (fk tas_preboarding on delete cascade);
  - doc_category text not null check in ('civil_id','passport','visa_residency','certificate','other');
  - label_en text; label_ar text; required boolean not null default true;
  - status text not null default 'pending' check in ('pending','collected','verified','waived');
  - document_id uuid (fk tas_document); waived_reason text; collected_at timestamptz; verified_at timestamptz;
  - created_at/created_by/updated_at/updated_by (+ trigger).
  - Unique index on (preboarding_id, doc_category) WHERE doc_category <> 'other' (allow multiple 'other'; partial predicate repeated in ON CONFLICT — rubric 12).
- RLS: both tables — authenticated SELECT; writes go through SECURITY DEFINER RPCs (no direct-table write policy); grants: authenticated SELECT. (Matches M1.x posture.)

## New permission key
- Seed `preboarding.manage` into `tas_permission` (area 'preboarding', name_en "Manage Pre-Boarding", name_ar "إدارة ما قبل الالتحاق", is_system false) — idempotent `on conflict (key) where key is not null do nothing`.
- Grant to SYSTEM_ADMIN, HR_MANAGER, RECRUITER (they collect/verify docs). `on conflict (role_id, permission_id) do nothing`.

## RPCs (SECURITY DEFINER, search_path=public; caller resolved from JWT oid/email; gate `preboarding.manage` before writes)
- `start_preboarding(p_application_id uuid) returns uuid` — resolve the application + its accepted offer; if a `tas_preboarding` already exists for the application return it (idempotent); else insert one and seed default checklist items: civil_id (required), passport (required), visa_residency (required), certificate (optional). Gate `preboarding.manage`. Audit `audit_log(...,'M1.10','preboarding.started',...)`. EXECUTE to authenticated.
- `set_preboarding_item(p_item_id uuid, p_status text, p_document_id uuid default null, p_reason text default null) returns void` — validate status in ('pending','collected','verified','waived'); set document_id/collected_at/verified_at/waived_reason accordingly; gate `preboarding.manage`. EXECUTE to authenticated.
- `complete_preboarding(p_preboarding_id uuid) returns void` — require every `required` item to be in ('collected','verified','waived') else raise 'preboarding_incomplete'; set status='completed', completed_at=now(), completed_by=caller; audit 'preboarding.completed'. Gate `preboarding.manage`. EXECUTE to authenticated.
- `preboarding_detail(p_id uuid) returns jsonb` — preboarding + candidate + application + items[] (with linked document meta). READ (open, authenticated) — reads stay open this module.
- `list_preboarding(p_status text default null, p_limit int default 50, p_offset int default 0) returns table(...)` — hires in pre-boarding (join candidate/application). READ (open, authenticated).
- Migration timestamp 14-digit, sorts after latest existing. No storage bucket SQL. No recursive CTEs. Idempotent (CREATE OR REPLACE, IF NOT EXISTS, ON CONFLICT). RLS + grants on new tables.
