# M2.1 — AI Recruitment Copilot (dormant adapter) (Spec)

## Objective
AI copilot scaffolding (JD generation, CV parsing, candidate ranking, screening assistant) built in the DORMANT-ADAPTER pattern: real LLM calls are gated behind `tas_ai_adapter_config` (disabled by default). Until an LLM API key is provisioned, the copilot returns a clear "dormant / not configured" response — no fake output. Bilingual EN/AR, RTL. New key `ai.use`. SYSTEM_ADMIN bypasses. Registers into the M3.2 unified adapter surface.

## Data model
- `tas_ai_adapter_config` — provider unique ('llm'); is_enabled default false; config_status ('unconfigured','configured'); model text; notes; +audit +trigger. Seed 'llm' disabled. NEVER stores secrets.

## New key
`ai.use` seeded (area 'ai') + granted SYSTEM_ADMIN, HR_MANAGER, RECRUITER.

## RPCs (gate ai.use)
- `ai_status()` → jsonb — adapter enable/config status (for the copilot UI).
- `ai_generate_jd(p_title text, p_notes text)` → jsonb — if adapter disabled → { dormant:true, message } (no LLM call); if enabled → best-effort invoke of the `ai-copilot` edge function (dormant stub). audit.
- Extend M3.2 `list_adapters()` / `set_adapter_enabled()` to include the `ai` kind (route to tas_ai_adapter_config).
- Migration: 14-digit ts sorts last; RLS+grants; ON CONFLICT rubric-12; no storage bucket literal; no recursive CTE; idempotent.

## Edge function (dormant stub)
- `supabase/functions/ai-copilot/index.ts` — checks adapter config; without LLM secret returns { dormant:true }. No external call until configured.

## Feature — src/features/ai
- api.ts (interim loose-cast), types.ts.
- Route `/app/ai` — AI Copilot: dormant status banner + a "Generate JD draft" form (title/notes → ai_generate_jd) that surfaces the dormant response until configured. Sidebar entry.
- Gate on `ai.use`; SYSTEM_ADMIN passes; loading→disabled.
