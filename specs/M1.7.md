# M1.7 — Interview Management (Spec)

## Objective
Schedule and manage interviews for shortlisted candidates: define rounds, assemble panels, schedule (with Outlook calendar + Teams meeting when M365 is configured — otherwise recorded in-app), capture per-interviewer scorecards (reusing the M1.6 scorecard infra), aggregate panel feedback, and record an outcome that drives the M1.5 pipeline. Direct recruiter action — NO workflow engine. M365 scheduling is a DORMANT adapter (works in-app now; Outlook/Teams creation activates when Graph credentials exist; degrades gracefully to 'skipped').

## Decisions (locked)
- Reuse M1.6 scorecard infra (tas_screening_scorecard + tas_screening_criterion) for interview scoring — a scorecard is a scorecard. Interview-specific data lives in new tas_interview_score / tas_interview_score_detail tables. Do NOT duplicate scorecard/criteria tables.
- Scheduling adapter: build the full interview engine + a DORMANT Outlook/Teams (Graph) adapter (same pattern as M0.4 notifications). Missing/unconfigured Graph -> calendar_status='skipped', no errors, interview still fully recorded in-app.
- Outcome model: DIRECT recruiter action. Recording outcome (proceed/reject/hold) drives the application via the EXISTING M1.5 move_application_stage / set_application_status. NO submit_workflow.
- Bilingual + RTL throughout; internal interview notes EN-only is fine.
- Writes: authenticated-callable via SECURITY DEFINER RPCs (recruiters schedule; panelists score their own), same pattern as M1.5/M1.6; table-level writes service-role.

### RPCs (security definer, transactional)
- schedule_interview(p_application_id uuid, p_round_type text, p_scheduled_at timestamptz, p_duration_min int, p_mode text, p_location text, p_panelist_ids uuid[], p_scorecard_id uuid): create tas_interview (ref via generate_interview_ref) + tas_interview_panelist rows; set calendar_status based on whether Outlook/Teams adapter is configured (read tas_comm_adapter_config / storage-style config — if outlook/teams not 'configured' -> 'skipped', else 'none' and the edge fn will set 'created'/'failed'); optionally move the application to an Interview-type stage via move_application_stage (resolve by stage_type='interview' or code; if none, skip move, no crash); notify() panelists 'interview.scheduled'; audit_log('M1.7','interview.scheduled',...). Returns interview id. Best-effort invoke the interview-schedule edge function for actual Graph calendar/Teams creation (fire-and-forget, never blocks).
- submit_interview_score(p_interview_id uuid, p_scores jsonb, p_recommendation text, p_notes_en text): resolve caller (JWT) as panelist (or service-role); upsert tas_interview_score (ON CONFLICT (interview_id, panelist_user_id) DO UPDATE — plain unique, fine) + tas_interview_score_detail rows (ON CONFLICT (interview_score_id, criterion_id) DO UPDATE); compute overall_score weighted by criterion weight (divide-by-zero -> null); set submitted_at. Authenticated.
- record_interview_outcome(p_interview_id uuid, p_outcome text): set interview.outcome + status='completed'; drive M1.5: proceed -> move_application_stage to next/post-interview stage (resolve sensibly; if ambiguous, leave stage, just record); reject -> move to stage_type='rejected' (fallback set_application_status 'rejected'); hold -> no move; notify 'interview.completed'; audit. Authenticated.
- reschedule_interview(p_interview_id uuid, p_new_datetime timestamptz): update scheduled_at; notify 'interview.rescheduled'; (best-effort calendar update via edge fn); audit. Authenticated.
- cancel_interview(p_interview_id uuid, p_reason text): status='cancelled'; notify 'interview.cancelled'; audit. Authenticated.
- interview_detail(p_id uuid): interview + panelists + scores (per panelist) + application/candidate summary. Authenticated.
- list_interviews(p_application_id uuid, p_status text, p_mine boolean, p_from timestamptz, p_to timestamptz, p_limit int, p_offset int): filtered, paged; p_mine = interviews where caller is a panelist (gate on currentUserId in UI). null filters ignored. Authenticated.
- interview_panel_summary(p_interview_id uuid): aggregated panel scores (each panelist overall + recommendation + average). Authenticated.
Grant EXECUTE to authenticated on all the above.

## Edge cases
- M365 not configured: scheduling records in-app, calendar_status='skipped', no calendar/Teams, no error. THIS IS THE DEFAULT STATE today.
- No Interview-type stage in pipeline: schedule still works; skip the stage move with a clear note, don't crash.
- Panelist submitting a scorecard for an interview they're not on: blocked (RPC checks panelist membership) — but until sign-in (currentUserId null), gate the UI and allow service-role; comment.
- Reschedule/cancel after completion: guard (don't reschedule a completed/cancelled interview) with a friendly message.
- Weighted overall with no scores: null, no divide-by-zero.
- currentUserId null (Entra last): "my interviews" + "submit my scorecard" stub gracefully; scheduled_by/panelist attribution null; no crash.
