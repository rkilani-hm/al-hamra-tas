# M1.8 — Assessment & Evaluation (Spec)

## Objective
Structured candidate assessment between interview (M1.7) and offer (M1.9): create a typed assessment per application (technical / psychometric / case study / other), score weighted criteria, compute a weighted overall, and record a recommendation (proceed / hold / reject). Bilingual EN/AR, RTL, RBAC via new key `assessment.write`. Mirrors the M1.6 screening / M1.7 scorecard patterns. SYSTEM_ADMIN bypasses.

## Data model
- `tas_assessment` — header: id; application_id (fk); candidate_id (fk); assessment_type ('technical','psychometric','case_study','other'); title; status ('draft','submitted') default 'draft'; overall_score numeric; recommendation ('proceed','hold','reject'); notes; assessed_by uuid; submitted_at; +audit +trigger.
- `tas_assessment_item` — id; assessment_id (fk cascade); label_en; label_ar; weight numeric default 1; score numeric; max_score numeric default 5; note; +audit +trigger.
- RLS: authenticated SELECT; writes via SECURITY DEFINER RPCs.

## New key
`assessment.write` seeded (area 'assessment') + granted SYSTEM_ADMIN, HR_MANAGER, RECRUITER, INTERVIEWER.

## RPCs (gate assessment.write)
- `create_assessment(p_application_id, p_type, p_title)` → uuid — create draft + seed 3 default items (Technical/Domain, Communication, Problem solving); audit.
- `save_assessment_items(p_assessment_id, p_items jsonb)` → numeric — upsert items by id; recompute weighted overall (sum(score*weight)/sum(weight) over scored items); persist; return overall.
- `submit_assessment(p_assessment_id, p_recommendation, p_notes)` → void — validate recommendation; set status='submitted', submitted_at, recommendation, notes; audit.
- `assessment_detail(p_id)` jsonb, `list_assessments(p_application_id, p_limit, p_offset)` table — reads open.
- Migration: 14-digit ts sorts last; RLS+grants; ON CONFLICT rubric-12 (item upsert keyed on id — plain pk); no storage bucket literal; no recursive CTE; idempotent.
