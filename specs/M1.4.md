# M1.4 — Careers Portal (Spec)

## Objective
Public, bilingual (EN/AR, RTL), mobile-first careers portal: browse published jobs and submit an application without signing in. Public applications land in the M1.5 ATS as candidates/applications with source='portal'. No RBAC key (public surface); access is via SECURITY DEFINER RPCs granted to `anon` + `authenticated`, scoped to published jobs only.

## Data access (public RPCs — SECURITY DEFINER, granted anon + authenticated)
- `list_public_jobs()` → table — published requisitions only (id, reference, title_en, title_ar, employment_type, department name, created_at).
- `public_job_detail(p_id)` → jsonb — a single published job + JD snapshot summary (returns null shell if not published).
- `submit_public_application(p_job_id, p_full_name, p_email, p_phone, p_nationality, p_cover)` → jsonb — job must be published; upsert candidate by email (partial-unique `where email is not null`, rubric 12), source='portal'; create application (dedup active) with source='portal'; return { application_id, reference }.
- No new table, no new permission key. Grants to `anon` are the public surface (scoped to published jobs / portal intake only).

## Routes (PUBLIC — top-level, outside the auth-gated /app layout)
- `/careers` — job list (public), bilingual/RTL, mobile-first, language toggle.
- `/careers/$id` — job detail + application form (name, email, phone, nationality, cover note) → submit_public_application; success confirmation with reference.

## i18n
Full `careers.*` namespace EN/AR (ar key-complete). No sidebar entry (public).

## Security notes
- anon EXECUTE is intentional and scoped: reads only published jobs; submit only creates portal candidate/application rows via definer. No table-level anon grants.
- Migration: 14-digit ts sorts last; ON CONFLICT rubric-12 on candidate email partial unique; no storage bucket literal; no recursive CTE; idempotent.

## DoD
tsc 0; /careers + /careers/$id 200 (public); ar parity; anon-granted RPCs; interim casts flagged.
