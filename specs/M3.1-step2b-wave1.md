# M3.1-step2b-wave1 — Enforcement Flip: Config (config.manage) (Spec)

## Objective
First enforcement wave. Flip the 15 config-write RPCs (from M3.1-step1) from the hardcoded _is_system_admin() gate to the data-driven _has_permission('config.manage') gate. Result: any role granted config.manage (SYSTEM_ADMIN via bypass, HR_MANAGER via the seeded grant) can manage config; roles without it are denied. This is the lowest-risk wave — it proves the enforcement pattern on a surface we just built and fully understand, before the recruiter-core (wave 2) and interview/offer/approval (wave 3) waves.

## Context
M3.1-step2a built the permission model: _has_permission(p_key) returns true if the caller is SYSTEM_ADMIN (bypass) OR holds a role granting that key. Seeded grants give config.manage to SYSTEM_ADMIN + HR_MANAGER. Today the config RPCs assert _is_system_admin() (SYSTEM_ADMIN only). This wave generalizes that to _has_permission('config.manage'). SYSTEM_ADMIN keeps working (bypass). Purely a gate swap inside existing RPCs — no schema, no new RPCs, no behavior change beyond WHO is authorized.

## Decisions (locked)
- Gate swap only: inside each of the 15 config_* RPCs, replace the _is_system_admin() assertion with: if not _has_permission('config.manage') then raise 'not_authorized'. Preserve every RPC body otherwise (CREATE OR REPLACE, same signature, same logic).
- SYSTEM_ADMIN still bypasses (built into _has_permission) — no regression for admin.
- UI: gate the config screens' write controls on useAuth().capabilities including 'config.manage' (instead of / in addition to the isSystemAdmin check from step1). A user with config.manage sees the Add/Edit/Save controls; others see read-only. SYSTEM_ADMIN sees everything (bypass reflected in capabilities — my_capabilities returns all keys for admin).
- No new permission keys, no catalog change, no new tables, no new RPCs. Reads unchanged (config reads already authenticated-open).
- This wave does NOT touch requisition/application/screening/interview/offer/approval (waves 2 and 3).
