# M1.3 — Candidate Sourcing & Talent Pool (Spec)

## Objective
Maintain a talent pool over M1.5 candidates with sourcing metadata (channel: internal / referral / agency / database / portal), tags, and pool status (active / passive / placed / archived). Bilingual EN/AR, RTL, RBAC via new key `sourcing.manage`. SYSTEM_ADMIN bypasses. Reuses tas_candidate (no candidate-schema change).

## Data model
- `tas_talent_pool` — id; candidate_id uuid unique (fk tas_candidate); source_channel ('internal','referral','agency','database','portal','other') default 'other'; agency_name text; referred_by text; tags text[] default '{}'; pool_status ('active','passive','placed','archived') default 'active'; notes; +audit +trigger.
- Index on (pool_status, source_channel). RLS authenticated SELECT; writes via SECURITY DEFINER RPCs.

## New key
`sourcing.manage` seeded (area 'sourcing') + granted SYSTEM_ADMIN, HR_MANAGER, RECRUITER.

## RPCs (gate sourcing.manage)
- `add_to_talent_pool(p_candidate_id, p_channel, p_agency, p_referred_by, p_tags jsonb, p_notes)` → uuid — upsert per candidate (idempotent); audit.
- `update_pool_status(p_id, p_status)` → void — validate status.
- `list_talent_pool(p_channel, p_status, p_limit, p_offset)` → table — join candidate name; filters. Read open.
- Migration: 14-digit ts sorts last; RLS+grants; ON CONFLICT rubric-12 (upsert on candidate_id unique); no storage bucket literal; no recursive CTE; idempotent.

## Feature — src/features/sourcing
- api.ts (interim loose-cast), types.ts.
- Route `/app/sourcing` — talent pool list (candidate, channel, tags, status) + filters + "Add to pool" dialog (candidate select from M1.5 candidates, channel, tags, notes). Sidebar entry.
- Capability gating `sourcing.manage`; reads open; loading→disabled; SYSTEM_ADMIN passes.
