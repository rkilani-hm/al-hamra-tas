# M2.7 — Candidate Sourcing Phase 1: Website (Careers Portal) intake, production-grade

**Goal:** turn the existing public careers apply (M1.4) into a complete website sourcing
channel: CV upload, candidate confirmation + recruiter notification (O365), source tagging,
anti-spam, and dormant-until-enabled AI CV enrichment — all feeding the one shared intake pipe
(candidate → application → pipeline + talent pool).

This is the first of the phased candidate-source plan:
Phase 1 Website (this spec) → Phase 2 LinkedIn (OIDC apply) → Phase 3 GCC boards (email intake).

## What already exists (reuse, do NOT rebuild)
- `submit_public_application(p_job_id, p_full_name, p_email, p_phone, p_nationality, p_cover)`
  → creates/merges `tas_candidate` (source='portal', dedupe by email) + `tas_application`.
  Granted to `anon`. (M1.4, migration 20260702150000)
- `tas_candidate.source`, M1.3 talent pool (`source_channel`, `add_to_talent_pool`).
- Document storage: private bucket `tas-documents` + `document-upload` edge fn (M0.5).
- `ai-copilot` edge fn `parse_cv` task (Lovable AI gateway; dormant until `llm` adapter enabled).
- O365 email adapter (Mail.Send, live) + `notify()` / notification-dispatch.
- Reports `applications_by_source` (M2.4) — source analytics already surfaces this channel.

## Deliverables

### 1. CV / résumé upload on the public apply form
- Add an optional file input (PDF/DOC/DOCX, ≤ 5 MB) to the careers apply form.
- Public upload path: a dedicated **`careers-upload` edge function** (anon-invokable, rate-limited)
  that validates type/size and stores the file in the private `tas-documents` bucket under
  `careers/{yyyy}/{uuid}.{ext}`; returns a `storage_ref`. (Do NOT expose the service key; the edge
  fn uses it server-side.) No public read of the bucket.
- Extend `submit_public_application` with `p_resume_ref text default null` (keep it last, defaulted,
  so the existing signature/overload resolution is preserved — drop+recreate to avoid an overload).
  Store the ref on the candidate/application (add `tas_candidate.resume_ref text` or a
  `tas_application.resume_ref`; prefer candidate-level so the CV follows the person). Link it as a
  `tas_document` row (entity_type='candidate') for the M0.5 document surface.

### 2. Source tagging = 'website'
- The public form is the **website** channel: pass source explicitly. Update
  `submit_public_application` to accept `p_source text default 'website'` (portal stays valid) and
  set `tas_candidate.source` + add the candidate to the talent pool with `source_channel='website'`.

### 3. Candidate confirmation + recruiter notification (O365 email, live)
- On successful apply: send the candidate a **confirmation email** (bilingual EN/AR template) via the
  live Outlook adapter; and **notify the requisition owner/recruiter** (in-app + email) that a new
  application arrived. Reuse `notify()` + notification templates (add `application.received` +
  `application.confirmation` templates, in_app + outlook_email, bilingual).
- Fully degrades: if email dormant, in-app still fires; never blocks the apply.

### 4. AI CV enrichment (dormant until the 'llm' adapter is enabled)
- After apply, best-effort call `ai-copilot` `parse_cv` with the uploaded CV text (extract text
  server-side in the edge fn where feasible; PDFs: pass through if text extraction is available,
  else skip) → enrich the candidate (skills, years_experience, current_title, full_name_ar) via a
  gated RPC `enrich_candidate_from_cv(p_candidate_id, p_fields jsonb)`.
- Returns dormant cleanly when the adapter is off (mirrors the M2.5 pattern). No candidate-facing
  dependency on AI.

### 5. Anti-spam / abuse
- Honeypot field + minimal server-side rate limit on the public RPC/edge fns (per-IP/email window).
- Basic validation (email format, required fields). No third-party captcha in Phase 1 (add later if
  spam appears).

## Non-goals (Phase 1)
- No custom domain (use `…/careers` for now; DNS mapping is a separate optional task).
- No job-board/LinkedIn intake (Phases 2–3).
- No résumé text extraction for scanned-image PDFs (OCR) — out of scope.

## Conventions / rubric
- Migration: 14-digit ts sorts last; RLS + grants; anon grants only where the public flow needs them;
  no storage bucket literal (reuse existing `tas-documents`); no recursive CTEs; ON CONFLICT matches
  real unique index (candidate email partial unique already exists). Drop+recreate
  `submit_public_application` (signature change) — update the anon/authenticated grant.
- New public edge fns (`careers-upload`) must be safe-by-default, validate hard, never leak secrets,
  and rate-limit. Bilingual EN/AR i18n parity maintained.
- Interim loose-cast in any new feature api.ts calling not-yet-typed RPCs; swap after Lovable regen.

## Dependencies from the user
- To start: none.
- To activate AI enrichment: enable the `llm` AI adapter (Administration → Integrations).
